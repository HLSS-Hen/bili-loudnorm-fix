# 响度均衡 · bili-loudnorm

一个单文件的 B 站用户脚本：**测量整段视频的响度，按需施加一个固定的增益**，把连播时忽大忽小的音量拉平。
不压缩原声、不干预播放器、不做版本检查，装进 Tampermonkey（或同类管理器）就能用。

> **代码来源**：本仓库的脚本代码全部由 **DeepSeek Harness + DeepSeek V4.1 Flash** 生成。

## 安装

1. 浏览器装 Tampermonkey（或 Violentmonkey / 同类管理器）；
2. 新建脚本，把 [`bili-loudnorm.user.js`](bili-loudnorm.user.js) 整段粘进去（或把文件直接拖进浏览器）；
3. 打开任意 B 站视频，播放器控制栏的**倍速右边**会多一个「响」；
4. **鼠标悬停在「响」上展开面板**，从「响」和面板上一起移开就自动收起。

> 不要和 `B站响度归一` 同时装：两者都会去抢同一个 `<video>` 的音频源，只有一个能拿到。

**快捷键 / 菜单**：`Shift + B` 旁路（听原声做 A/B）；油猴菜单里有「开关响度均衡 / 旁路开关 / 清空测量缓存」。

## 它做什么

打开视频 → 读 `__playinfo__` 里的 DASH 音频索引（sidx）→ 等距抽 12 段（约 57 秒音频）
→ 逐段解码、按 ITU-R BS.1770-4 算整片集成响度 → 用「目标响度 − 实测响度」得到一个
**整片恒定的增益** → 通过 Web Audio 以 **100ms 淡入淡出**落位，不硬切。

B 站元数据可用时（`measured_i` 且不是 `0.001` 占位）直接走快路径，不下载任何音频片段。

### 不等整轮抽完

本地抽样时**第一段音频一到就先落位**，之后**每 500ms 重算一次**（这一拍没有新片段就空过，
等下一拍）。片段陆续到达时增益会被逐步修正，全部抽完再收一个终值。所以首屏不用干等几秒，
听感上是「一开始就对个大概，越听越准」。修正死区 0.2 dB：预估变化小于它就不重复淡变，避免来回抖。

### 取片段：403 / 超时怎么处理

- **先走页面 `fetch`**（B 站 CDN 带 `Access-Control-Allow-Origin`，最快也最不容易被挡）；
- fetch 失败（CORS / 网络）才退 `GM_xmlhttpRequest`，并且**必带 `Referer: https://www.bilibili.com/`**
  —— 不带 Referer 会被 CDN 防盗链直接回 `403`；
- 服务端若忽略 `Range` 回 200 整包，本地按 `start` 切出需要的那段；
- 单段失败（超时 / 5xx / 解码失败）**只丢这一段**，不会把整次分析判死；主地址失败还会换
  `backupUrl` 再试一次。成功段数 < 3 才放弃，绝不拿残数据算增益；
- 请求带 80ms 启动间隔（`requestGapMs`），避免短时间连发被 CDN 限流。

## 覆盖范围

| 页型 | 说明 |
| --- | --- |
| `/video/BV...` | 普通投稿、多 P（按 `?p=` 区分，各自独立缓存） |
| `/list/...` | 列表页（bvid 从查询串取） |
| `/bangumi/play/ep...` `ss...` | 番剧/影视/纪录片/国创/综艺；`ss` 落地页会认当前在播的那一集 |

课程页、直播页不在 `@match` 里，脚本根本不会加载。

## 选集 / 换集之后，还能用 B 站的响度参数吗

能，但 B 站自己没做到，得靠脚本补。

**原因不是「所有分集共用一份均衡」。** 换集时播放器会把响度模块 dispose 再重建。
真正的问题是**数据没跟着换**：

- B 站的响度元数据（`volume.measured_i` / `measured_tp`）只随**首屏 SSR 的 `__playinfo__`** 下发；
- 运行时换集走的是 `x/player/playurl` 接口，而这个接口的响应里**根本没有 `volume` 字段**；
- 所以换集后播放器手里没有新一集的数字，只能保持/复位。

脚本的取法（`PlayInfo.get`）：

1. 页面里的 `__playinfo__` 且时长对得上 → 直接用（零请求）；
2. 对不上 / 没有 → 调 `x/player/playurl`（**它没有元数据**，只用来拿音频轨地址）；
3. 还是没有元数据 → **回读这一集的页面 SSR**，把 `window.__playinfo__` 抠出来继续用 B 站的数字；
4. SSR 也没有（比如那一集没测过响度）→ 才走本地抽样；之后播放中还会再问一次 B 站，
   拿到官方值就自动升级（见下面「缓存」）。

第 3 步的代价是一次整页请求（约 0.5–1MB），只在「接口缺元数据」时发生；
不想要可以 `__bln._.CFG.ssrMeta = false` 关掉，关掉后选集就回到本地抽样。

## 选集 / 换集不崩的原因

一个 `<video>` 只能被一个 `AudioContext` 拿到 `createMediaElementSource()`。
脚本先抢到之后，B 站播放器换集时会**再要一次**，原生直接抛 `InvalidStateError`；
B 站那侧的 `this.gain` 于是永远没被赋值，它的
`onDispose → turnOffLoudnessNormalization → setGain` 就会崩在
`Cannot read properties of undefined (reading 'gain')`，换集 promise 链被打断，
于是「新一集不播」。

脚本在 `document-start` 就给 `AudioContext.prototype.createMediaElementSource` 装了守卫：
同一个元素第二次被要时，返回一个**同 context 的静音 GainNode**（带 `mediaElement` 兜底属性），
B 站拿到节点就不会抛，dispose 正常走完，换集正常。

反过来，如果是 B 站先占了音频源，脚本拿到的是哑节点，会识别出来并保持原声
（面板显示「音频源被占用」），不会去做无效的增益。

## 界面

- 控制栏里多一个**「响」**，位置在**倍速右侧、音量左侧**。按钮节点就是原生结构，一个多余的类、
  一条内联样式都没有：`<div class="bpx-player-ctrl-btn" title="响度均衡" role="button">`
  里放 `<div class="bpx-player-ctrl-playbackrate-result">响</div>`，字号/行高/内边距全交给
  B 站自己的 CSS；`order` 也从倍速按钮上取，改成用样式表下发，所以看着就是原生按钮之一。
- **悬停「响」展开面板**；面板是「响」这个 `bpx-player-ctrl-btn` 里的子节点（和原生设置/清晰度菜单
  同一位置），鼠标从「响」和面板上一起离开约 0.2 秒后收起。点空白处或按 `Esc` 也会关。
- 面板**贴着进度条**往上弹（底边压在进度条上沿上方 2px）：以 `.bpx-player-progress-wrap` /
  `.bpx-player-control-bottom` 的上沿为基准算，探不到才退回「按钮上沿 +16px」；
  播放器太矮时面板内部滚动，不会顶出画面。
- 面板**直接复用播放器自带的组件**，不是自己画的：

  | 部位 | 用的官方标记 |
  | --- | --- |
  | 面板外壳 | `.bui.bui-panel.bui-dark`（背景 / 圆角 / 阴影都是播放器的） |
  | 内边距与栅格 | `.bpx-player-ctrl-setting-menu-right`（和官方设置面板右侧同一套） |
  | 预设选择 | `.bui-radio.bui-radio-button` + `.bui-radio-item` / `.bui-radio-input` / `.bui-radio-label` / `.bui-radio-text` |

  选中态用官方变量 `--bpx-fn-color`（默认 `#00a1d6`），所以换皮肤、跟随主题都自动生效。

  | 缓存 | `缓存 0 / 2233 条` + 「清空」 |

- 关掉均衡时标题行只显示「已关闭」，`[官]/[本]` 和「重新获取」一起收起；「已关闭」只出现在这一行。
- 增益被限幅（峰值挡着 / 提升上限 / 衰减下限）时**面板上不做任何标注**，鼠标停在 dB 值上才显示原因。
- 面板里**不设浅灰次要文字**：状态、数值、`重新获取`、`清空` 一律白色，只靠字号和位置分主次。
- 旁路不在面板里，仍可用 `Shift + B` 或油猴菜单切换。
- 控制台只在 `warn` / `error` 时说话；`__bln.debug(true)` 才会把 info/debug 全放出来，
  平时想复盘看 `__bln.logs()`。

### 「响」看不见怎么办

部分版本的 B 站把字号写在后代选择器里（`.bpx-player-ctrl-playbackrate .bpx-player-ctrl-playbackrate-result`），
外来的 `bpx-player-ctrl-btn` 只会继承到 0 号字 —— 字看不见、盒子还在（给盒子染色能看出位置是对的）。
脚本每次插入按钮时会把原生那个文字的 **字号 / 行高 / 字体 / 颜色** 量一遍，写进一张样式表兜底，
并强制 `-webkit-text-fill-color:currentColor`、`opacity:1`、`visibility:visible`。

真机上还是看不到的话，控制台跑这一行，把结果贴到 issue 里：

```js
var b = document.querySelector('.bpx-player-ctrl-btn[title="响度均衡"]');
var s = getComputedStyle(b.firstElementChild);
[s.fontSize, s.lineHeight, s.color, s.webkitTextFillColor, s.visibility, s.opacity, s.display].join(' | ')
```

## 预设

五档取自上游仓库，另加一个「关闭」并进同一个按钮组：

| 预设 | 目标响度 | 提升上限 | 适用 |
| --- | --- | --- | --- |
| 标准（默认） | −14 LUFS | +12 dB | 对齐 B 站「音量均衡·标准」档 |
| 高动态 | −24 LUFS | +12 dB | 对齐 B 站「音量均衡·高动态」档 |
| 深夜 | −20 LUFS | +6 dB | 怕吵到人 |
| 耳机 | −16 LUFS | +12 dB | 夜间用耳塞 |
| 外放 | −11 LUFS | +10 dB | 手机外放 / 小音箱 |
| 关闭 | — | — | 关掉均衡，输出原声 |

选任意一档 → 立刻用缓存里的测量值重算增益（零下载），没测量值就顺带触发一次分析；
选「关闭」= 关掉均衡。选择会存进设置，下次打开还是它。

增益的计算顺序（`GainPlan.plan`）：

```js
gain = 目标 − 实测                       // 理想增益
gain = min(gain, maxBoost)              // 别抬太狠
gain = max(gain, minGain)               // 别压太狠（-60 dB 地板）
gain = min(gain, max(0, -1dBTP − 真峰值)) // 别削波，且绝不为负
```

## 缓存

存的是**测量值**（不是增益），所以换目标 / 换预设永远命中，不会重新取流。

| 项 | 说明 |
| --- | --- |
| 键 | `bln:m:<BV1xx:pN>` / `bln:m:ep<id>` |
| 内容 | `{ i: 响度, tp: 真峰值, d: 时长, src: 'meta'\|'sample', at }` |
| 上限 | 2233 条；超了按「最久未用」淘汰 |
| TTL | 30 天 |
| 清理 | 面板「清空」/ 油猴菜单 / `__bln.cache.clear()` / 单条「重新获取」 |

`src` 记录这一条是**官方测的**还是**本地算的**。本地算的那种，脚本会在播放约 1 分钟后
回头问一次 B 站（`PlayInfo.officialMeta`，只回读该集页面 SSR）：

- 官方已经测好 → 删掉本地缓存、写入官方值，按新值重算增益并 100ms 淡变落位；
- 还没测好 → 5 分钟后再试一次，之后就不再打扰；
- 视频暂停时不会发这个请求，等真正在播再查。

## 控制台接口

```js
__bln.status()        // 页型、状态、实测值、增益、引擎、缓存、视频信息一把梭
__bln.reanalyze()     // 丢掉当前视频的缓存并重测
__bln.bypass(true)    // 旁路
__bln.preset('night') // 切预设：standard / dynamic / night / headphone / speaker / 'off'
__bln.presets()       // 列出五档预设
__bln.setTarget(-16)  // 直接改目标响度（会记成 custom，按钮组不再高亮）
__bln.cache.stats()   // 缓存条数
__bln.cache.clear()
__bln.logs()          // 环形日志（最近 400 条）
__bln.debug(true)     // 打开调试日志
__bln._               // 内部模块（Sidx / Loudness / GainPlan …），排障用
```

## 已知限制

- **纯线性增益**，没有压缩器、没有限幅器。增益的峰值预算按真峰值 −1 dBTP 卡，
  抽到的只是样点峰值，所以额外留了 0.7 dB 余量。
  素材本身已经顶到满刻度时，**只会把增益停在 0 dB，不会反过来把声音调小**。
  所以「实测 −22.2、目标 −14」却显示 `+0.00 dB` 是正常的：这条视频抽到的峰值
  离满刻度只差不到 1 dB，硬提 +8.2 dB 会削波。
- 抽样是等距取段，可能漏掉局部极响的片段（这也是它不做「局部处理」的代价）。
  渐进落位意味着前几秒的增益只是「按已到达的片段估的」，末尾会再修正一次。
- 首次打开一个没缓存的视频要等几秒才能抽完；看过的会命中缓存，秒进。
- 番剧接口那条路不带响度元数据，只能走抽样；试看/地区限制/版权限制会直接报错并保持原声。
- 如果 B 站自己先占了音频源（例如「音量均衡」开着且比脚本更早建图），本次不做调整。
- Firefox 的脚本沙箱可能改不动原生 prototype，守卫会安装失败（控制台会有告警），
  此时换集仍有崩溃风险 —— 这是浏览器沙箱限制，不是脚本逻辑问题。

# 响度均衡 · bili-loudnorm

一个单文件的 B 站用户脚本：**测量整段视频的响度，按需施加一个固定的增益**，把连播时忽大忽小的音量拉平。
不压缩原声、不干预播放器、不做版本检查，装进 Tampermonkey（或同类管理器）就能用。

> **代码来源**：本仓库的脚本代码全部由 **DeepSeek Harness + DeepSeek V4.1 Flash** 生成。

## 安装

1. 浏览器装 Tampermonkey（或 Violentmonkey / 同类管理器）；
2. 新建脚本，把 [`bili-loudnorm.user.js`](bili-loudnorm.user.js) 整段粘进去（或把文件直接拖进浏览器）；
3. 打开任意 B 站视频，播放器控制栏的**倍速右边**会多一个「响」；
4. **鼠标悬停在「响」上展开面板**，从「响」和面板上一起移开就自动收起。

> 不要和 `B站响度归一` 同时装：两者都会去抢同一个 `<video>` 的音频源，只有一个能拿到。

**菜单**：油猴菜单里有「切换响亮 / 标准 / 安静」和「清空测量缓存」。

## 它做什么

打开视频 → 读 `__playinfo__` 里的 DASH 音频索引（sidx）→ 等距抽 12 段
→ 逐段解码、按 ITU-R BS.1770-4 算整片集成响度 → 用「目标响度 − 实测响度」得到一个
**整片恒定的增益** → 通过 Web Audio 以 **100ms 淡入淡出**落位，不硬切。

B 站官方响度可用时（`measured_i` 且不是 `0.001` 占位）直接走快路径，不下载任何音频片段。

### 不等整轮抽完

本地抽样时**第一段音频一到就先落位**，之后**每 500ms 重算一次**（这一拍没有新片段就空过，
等下一拍）。片段陆续到达时增益会被逐步修正，全部抽完再收一个终值。所以首屏不用干等几秒，
听感上是「一开始就对个大概，越听越准」。修正死区 0.2 dB：预估变化小于它就不重复淡变，避免来回抖。

### 取片段：403 / 超时怎么处理

- **先走页面 `fetch`**（B 站 CDN 带 `Access-Control-Allow-Origin`，最快也最不容易被挡）；
- fetch 失败（CORS / 网络）才退 `GM_xmlhttpRequest`，并且**必带 `Referer: https://www.bilibili.com/`**
  —— 不带 Referer 会被 CDN 防盗链直接回 `403`；
- 服务端若忽略 `Range` 回 200 整包，本地按 `start` 切出需要的那段；
- 单段失败（超时 / 5xx / 解码失败）**只丢这一段**，不会把整次分析判死；主地址失败还会换
  `backupUrl` 再试一次。成功段数 < 3 才放弃，绝不拿残数据算增益；
- 请求带 80ms 启动间隔（`requestGapMs`），避免短时间连发被 CDN 限流。

## 覆盖范围

| 页型 | 说明 |
| --- | --- |
| `/video/BV...` | 普通投稿、多 P（按 `?p=` 区分，各自独立缓存） |
| `/list/...` | 列表页（bvid 从查询串取） |
| `/festival/...` | 活动页（bvid 在查询串里；官方响度按该视频的标准落地页取） |
| `/bangumi/play/ep...` `ss...` | 番剧/影视/纪录片/国创/综艺；`ss` 落地页会认当前在播的那一集 |

课程页、直播页不在 `@match` 里，脚本根本不会加载。

## 选集 / 换集之后，官方响度还拿得到吗

能，但 B 站自己没做到，得靠脚本补。

**原因不是「所有分集共用一份均衡」。** 换集时播放器会把响度模块 dispose 再重建，
真正的问题是**数据没跟着换**：

- B 站的响度元数据（`volume.measured_i` / `measured_tp`）只随**首屏 SSR 的 `__playinfo__`** 下发；
- 运行时换集走的是 `x/player/playurl` 接口，而这个接口的响应里**根本没有 `volume` 字段**；
- 所以换集后播放器手里没有新一集的数字，只能保持/复位。

脚本的取法（顺序固定为「官方优先」）：

1. 页面里的 `__playinfo__` 且时长对得上 → 直接用（零请求）；
2. 对不上 / 没有 → 调 `x/player/playurl`（**它没有元数据**，只用来拿音频轨地址）；
3. 接口没给响度 → **回读这一集的页面 SSR**，把 `window.__playinfo__` 抠出来用 B 站的数字；
4. 官方也没有（比如那一集没测过）→ 才走本地抽样；播放中还会再问一次 B 站，
   拿到官方值就自动升级（见「缓存」）。

**关于「选集时倾向于本地算」**：根因是**缓存先命中了本地值**。早先在某一集本地抽样过一次，
之后不论怎么切回这一集都会直接吃那条缓存，压根不再看 B 站测没测。现在命中缓存的本地条目
也会先问一次官方值，问到了就当场替换（面板备注写「已换成 B 站官方值」），问不到才继续用本地值。

**SSR 回读的地址规则**（这一条踩过坑，改之前先看实测结论）：

- 官方响度只存在于**标准落地页** `/video/BVxxxx` 的 SSR 里（`__playinfo__.data.volume`）；
- 活动页 `/festival/*` 和列表页 `/list/*` 的 HTML **只是播放器外壳**，整页搜不到
  `__playinfo__` / `measured_i`（实测 900KB 的页面里一个都没有），它们的播放器自己
  也是走 `x/player/wbi/playurl`，而那个接口**从不返回 `volume`**——
  拿普通视频的 cid 直接调也一样没有；
- 所以脚本只在「当前页就是 `/video/<这个 bvid>` 且 p 相同」时才读当前页，
  其余情况（活动页、列表页、同一视频的其它集）**一律回落到 `/video/BVxxxx?p=N`**。

番剧则始终按 `ep` 地址回读（`/ss` 的当前页只带第一集）。

> 例外：有少数 bvid 本身就被 B 站托管在活动页里（例如 `/festival/S16?bvid=BV1Ka4J6TEBo`），
> 它的 `/video/BV1Ka4J6TEBo` 返回的也是同一个活动页外壳。这种视频**任何地方都没有官方响度**，
> 只能本地抽样，面板会如实显示 `[本]`。

第 3 步的代价是一次整页请求（约 0.5–1MB），一集一次；
不想要可以 `__bln._.CFG.ssrMeta = false` 关掉，关掉后选集就回到本地抽样。

## 选集 / 换集不崩的原因

一个 `<video>` 只能被一个 `AudioContext` 拿到 `createMediaElementSource()`。
脚本先抢到之后，B 站播放器换集时会**再要一次**，原生直接抛 `InvalidStateError`；
B 站那侧的 `this.gain` 于是永远没被赋值，它的
`onDispose → turnOffLoudnessNormalization → setGain` 就会崩在
`Cannot read properties of undefined (reading 'gain')`，换集 promise 链被打断，
于是「新一集不播」。

脚本在 `document-start` 就给 `AudioContext.prototype.createMediaElementSource` 装了守卫：
同一个元素第二次被要时，返回一个**同 context 的静音 GainNode**（带 `mediaElement` 兜底属性），
B 站拿到节点就不会抛，dispose 正常走完，换集正常。

反过来，如果是 B 站先占了音频源，脚本拿到的是哑节点，会识别出来并保持原声
（面板显示「音频源被占用」），不会去做无效的增益。

### 「响」看不见怎么办

部分版本的 B 站把字号写在后代选择器里（`.bpx-player-ctrl-playbackrate .bpx-player-ctrl-playbackrate-result`），
外来的 `bpx-player-ctrl-btn` 只会继承到 0 号字 —— 字看不见、盒子还在（给盒子染色能看出位置是对的）。

## 预设

三档对齐 Spotify 的播放响度档位（Loud / Normal / Quiet），没有「关闭」——脚本常驻，想彻底停用请直接关掉油猴脚本：

| 预设 | 目标响度 | 提升上限 | 峰值处理 | 适用 |
| --- | --- | --- | --- | --- |
| 响亮（Loud） | -11 LUFS | +16 dB | **忽略峰值预算，启用限幅器** | 和 Spotify「响亮」档同口径 |
| 标准（Normal，默认） | -14 LUFS | +16 dB | 峰值预算：只挡提升，不把声音压小 | 对齐 Spotify「标准」与 B 站「标准」档 |
| 安静（Quiet） | -19 LUFS | +16 dB | 同上 | 夜间 / 怕吵到人 |

选任意一档 → 立刻用缓存里的测量值重算增益（零下载），没测量值就顺带触发一次分析。选择会存进设置，下次打开还是它；旧版的五档（标准 / 高动态 / 深夜 / 耳机 / 外放 / 关闭）会自动迁移到最近的一档。

「响亮」档的限幅器（`DynamicsCompressorNode`，`master → limiter → destination`）：

```js
threshold = -2.0 dBFS   // 比 Spotify 的 -1 dB 再收 1 dB，给真峰值留余量
ratio     = 20
attack    = 0.005 s     // 与 Spotify Loud 一致
release   = 0.100 s     // 与 Spotify Loud 一致
```

标准 / 安静档**不把限幅器接进链路**：`master` 直连 `destination`，所以没有那 6 ms 的 look-ahead 延迟；只有在切到「响亮」档时才会重新接线（`master → limiter`），代价是切换瞬间可能有极轻的断点——切预设本来就伴随一次 100 ms 增益淡变，实际听不出来。

增益的计算顺序（`GainPlan.plan`）：

```js
gain = 目标 − 实测                          // 理想增益
gain = min(gain, maxBoost)                 // 别抬太狠
gain = max(gain, minGain)                  // 别压太狠（-60 dB 地板）
gain = min(gain, max(0, ceiling − 真峰值))  // 别削波；ceiling = -1 dBTP
```

峰值这一条**只会把增益往下压到 0，绝不会压成负数** —— 即「峰值只挡提升，绝不把声音调小」。

## 缓存

存的是**测量值**（不是增益），所以换目标 / 换预设永远命中，不会重新取流。

| 项 | 说明 |
| --- | --- |
| 键 | `bln:m:<BV1xx:pN>` / `bln:m:ep<id>` |
| 内容 | `{ i: 响度, tp: 真峰值, d: 时长, src: 'meta'\|'sample', at }` |
| 上限 | 2233 条；超了按「最久未用」淘汰 |
| TTL | 30 天 |
| 清理 | 面板「清空」/ 油猴菜单 / `__bln.cache.clear()` / `__bln.reanalyze()` |

`src` 记录这一条是**官方测的**还是**本地算的**。本地算的那种，脚本会在播放约 1 分钟后
回头问一次 B 站（`PlayInfo.officialMeta`，只回读该集页面 SSR）：

- 官方已经测好 → 删掉本地缓存、写入官方值，按新值重算增益并 100ms 淡变落位；
- 还没测好 → 5 分钟后再试一次，之后就不再打扰；
- 视频暂停时不会发这个请求，等真正在播再查。

## 控制台接口

```js
__bln.status()        // 页型、状态、实测值、增益、引擎、缓存、视频信息一把梭
__bln.reanalyze()     // 丢掉当前视频的缓存并重测
__bln.preset('loud')  // 切预设：loud / normal / quiet（响亮 / 标准 / 安静）
__bln.presets()       // 列出三档预设
__bln.setTarget(-16)  // 直接改目标响度（会记成 custom，按钮组不再高亮）
__bln.cache.stats()   // 缓存条数
__bln.cache.clear()
__bln.logs()          // 环形日志（最近 400 条）
__bln.debug(true)     // 打开调试日志
__bln._               // 内部模块（Sidx / Loudness / GainPlan …），排障用
```

## 已知限制

- **标准 / 安静档是纯线性增益**，没有压缩器、没有限幅器；峰值预算按真峰值 -1 dBTP 卡，
  而抽到的只是样点峰值，所以额外留了 0.7 dB 余量。
- **响亮档会限幅**：忽略峰值预算，靠 `DynamicsCompressorNode` 把超出 -2 dBFS 的峰值压住，
  代价是那一段的瞬态被压缩，且这条链路多 6 ms look-ahead 延迟。
- 素材本身已经顶到满刻度时，**只会把增益停在 0 dB，不会反过来把声音调小**。
  所以「实测 -16.0、目标 -14」却显示 `+0.0 dB` 是正常的：这条视频的官方真峰值
  `measured_tp = 0.3 dBFS`，`-1.0(ceiling) − 0.3 = 0.00`，预算为 0，再提就削波。
  面板这时会显示 `-16.0 → -16.0 LUFS [限]`。
- 抽样是等距取段，可能漏掉局部极响的片段（这也是它不做「局部处理」的代价）。
  渐进落位意味着前几秒的增益只是「按已到达的片段估的」，末尾会再修正一次。
- 首次打开一个没缓存的视频要等几秒才能抽完；看过的会命中缓存，秒进。
- 番剧接口那条路不带响度元数据，只能走抽样；试看/地区限制/版权限制会直接报错并保持原声。
- **未付费的充电专属视频**拿到的是 mp4 整包（`durl`，只有约 180 秒试看），没有 DASH 音轨、也没有
  `volume` 元数据，既不能按整片测也没法便宜地测。这种情况**不做降级测量**，直接报
  `充电专属未付费` 并保持原声。付费后接口会给回 DASH，照常按整片测。
- 如果 B 站自己先占了音频源（例如「音量均衡」开着且比脚本更早建图），本次不做调整。
- Firefox 的脚本沙箱可能改不动原生 prototype，守卫会安装失败（控制台会有告警），
  此时换集仍有崩溃风险 —— 这是浏览器沙箱限制，不是脚本逻辑问题。

## 自测

纯 Node、零依赖，桩掉了 DOM / AudioContext / GM 接口：

```bash
node test/selfcontained.test.mjs     # 203 项
```

覆盖：

- **响度算法**：K 加权 48kHz 系数与 BS.1770 标准值逐项比对、积分响度（单/双声道差 3.01 dB、
  幅度 ×2 → +6 dB、静音、峰值）；
- **取流**：sidx 解析与偏移、等距抽样、Range 请求策略（fetch 优先、GM 补 Referer、200 整包切片）；
- **增益**：规划（含峰值预算不下压）、显示格式（一位小数、`+0.0`、不留 `-0.0`）；
- **端到端**：元数据快路径、sidx 抽样（含「第一段先落位、全部抽完再修正」）、
  「个别片段 503 也能出结果」、「接口没有 volume → 回读该集 SSR 继续用官方值」、
  「本地值播放中自动升级成官方值」；
- **缓存**：过期清理、命中刷新、LRU 淘汰与上限、手动清空；
- **音频源守卫**：第二次索取返回哑节点、换集不重复建图；
- **界面**：按钮插入位置、面板打开/关闭、「响」的字号兜底、预设切换、信息行各状态的文案与对齐。

真机（线上播放器）没有自动化覆盖，第一次用建议开一个带选集的页面连换 5 集看看。
